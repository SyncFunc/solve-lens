# 宝宝巴士做题助手需求文档

## 1. 产品定位

宝宝巴士是一个运行在 Windows 10 2004 及以上版本、面向学习和练习场景的快捷做题助手。用户通过全局快捷键连续截取题目图片，选择题型后提交给本机解题 Provider；答案以流式文本和 Markdown 形式实时显示在置顶浮窗、配置窗口以及局域网手机页面中。

产品不执行图片中的指令，不访问与答题无关的本地资源。它只用于允许辅助工具的学习和练习场景。

## 2. 窗口与显示

应用包含配置窗口和答案浮窗。配置窗口负责任务状态、Provider、模型、Prompt、快捷键、窗口样式和局域网控制设置；关闭配置窗口时应用进入系统托盘，不退出进程。托盘菜单可重新打开配置窗口或退出应用。

答案浮窗始终置顶、无焦点、鼠标点击穿透，仅通过快捷键控制。窗口使用 `WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE` 和 `WDA_EXCLUDEFROMCAPTURE`；保护属性设置或读回失败时禁止展示答案。该保护只针对常见 Windows 捕获 API，不保证防止相机、采集卡或特权录制程序。

浮窗支持背景透明度、字体大小、窗口宽高、移动和主题设置。主题包括日间、夜间和实时取色跟随；跟随模式从浮窗后方多个采样点计算背景颜色，并自动选择具有对比度的文字颜色。透明度、字体大小和窗口位置快捷键调整后立即生效。浮窗隐藏后，截图、提交和解题完成不会自动唤出，只有显隐快捷键可以重新显示。

## 3. 截图草稿

一次题目由一个 `QuestionDraft` 表示，包含草稿 ID、题型预设 ID、创建时间、状态和按捕获顺序排列的图片引用。单个草稿最多 6 张图片，图片达到上限后必须提交或清空。截图前不隐藏浮窗，依赖捕获排除属性避免浮窗内容进入截图。

默认题型快捷键为：`Ctrl+Alt+1` 通用、`Ctrl+Alt+2` 数学、`Ctrl+Alt+3` 代码。同一快捷键重复触发会向当前草稿追加图片；当前草稿绑定首张图片选择的题型，切换其他题型时拒绝混合并提示先提交或清空。配置窗口和手机页面均显示完整截图预览及图片数量。

## 4. 题型预设与 Prompt

预设字段包括 `id`、名称、内置标识、快捷键、任务模板和版本号。内置通用、数学、代码预设可直接编辑；也可以复制生成自定义预设。通用模板要求识别题目并直接作答；数学模板要求转写题意、展示关键推导并核对单位和选项；代码模板要求识别语言、定位错误或实现要点并给出可执行解法。

每次请求由不可修改的安全规则、预设任务模板、草稿元数据、全局附加要求和按顺序附加的图片组成。全局附加要求可在配置页编辑，例如语言、答案长度或输出风格。安全规则始终保留。

## 5. Provider 与模型

Provider 配置为独立卡片，可在 Codex CLI 和 Claude Code CLI 之间切换。Codex CLI 使用本机安装并登录的 CLI，支持配置路径、超时和模型；模型列表在启动和 Provider 切换后自动从 Codex CLI 读取，模型候选显示名称、标识和当前生效模型，每次请求通过 `--model` 传入。Claude Code CLI 显示独立路径、超时和可选模型配置，当前版本保留适配入口。

Codex 调用使用临时工作目录和只读沙箱，传入 `--image` 的顺序与草稿顺序一致。任务完成、取消、异常和超时都清理临时图片；超时或取消会终止整个 CLI 子进程树。Provider 输出保持原始文本，不强制套用结构化答案格式。

## 6. 流式输出与 Markdown

解题过程中，Provider stdout 的每一行都作为增量事件处理，兼容 JSON 事件和纯文本增量。后端更新 `stream_output` 后立即发布状态事件；前台浮窗、配置窗口和手机页面收到事件后立即刷新，不等待最终答案。

Markdown 使用开源 `marked` 解析，并通过 `DOMPurify` 清理 HTML。渲染范围包括 GFM 标题、段落、粗体、斜体、删除线、链接、图片、引用、有序/无序列表、任务列表、代码块、行内代码、表格、分隔线和换行。列表中的单独短横线不得被误判为分隔线。答案支持按页面翻阅，字体大小变化后重新计算分页。

## 7. 快捷键

快捷键包括三种题型截图、提交、清空、取消、显隐浮窗、上一页、下一页、字体增减、透明度增减和窗口上下左右移动。配置输入框支持用户直接按下组合键录入。保存时在对应配置项旁显示冲突，不允许重复绑定；快捷键不得覆盖系统保留组合键，是否必须包含 Ctrl 由配置校验规则决定。

## 8. 局域网手机控制

局域网控制默认关闭。开启后服务绑定 `0.0.0.0`，端口范围为 1024–65535，手机通过 `http://电脑IP:端口` 访问。服务提供手机控制页面、状态查询、截图、提交、清空和取消接口，并支持 WebSocket 状态事件；WebSocket 断开时自动退回无缓存轮询。

事件模型至少包含 `DraftChanged`、`StreamChunk`、`AnswerReady`、`TaskStatusChanged` 和 `Error`。`DraftChanged` 默认只同步题型、数量和缩略图；完整图片自动保存由开关控制。手机控制按钮必须足够大，具有按压反馈、发送中状态、成功状态和失败状态。截图成功必须在服务确认草稿图片数量增加后才提示成功；提交成功必须在状态进入答案完成后才提示成功。

手机页面显示任务状态、完整截图预览、流式输出和最终答案。连接失败时只显示连接提示，不覆盖已经显示的答案，也不得把异常对象文本闪烁到答案区域。状态响应使用 `Cache-Control: no-store`。

## 9. 历史与隐私

历史索引使用 SQLite 保存，题图和答案使用 AES-256-GCM 加密，主密钥由当前 Windows 用户 DPAPI 保护。默认保留 30 天，支持立即清空。手机端默认不同步历史图片；自动保存完整截图开关只影响当前手机浏览器接收和保存行为。

## 10. 状态与错误

任务状态至少包括空闲、截图中、待提交、求解中、展示中、已取消和失败。配置无效、Provider 未登录、CLI 路径不存在、模型不可用、端口占用、保护属性失败、超时、取消、异常 JSON 和网络断连都必须给出可理解的中文提示，并保留上一次可用答案。

## 11. TS + React 前端要求

配置窗口、答案浮窗和手机控制页面的界面层统一采用 TypeScript + React。状态通过单一快照模型和事件订阅驱动，组件不得依赖定时器直接改写业务状态。Markdown 内容必须经过解析和清理后再进入 DOM。按钮、Toast、弹窗、候选框、滑块和滚动区域使用统一组件样式，支持键盘操作、焦点可见性和窄屏布局。

## 12. 验收标准

验收必须覆盖：单图和 6 图顺序、跨题型冲突、快捷键冲突提示、预设编辑与复制、模型切换、Codex 参数顺序、纯文本和 JSON 流式输出、实时 Markdown、超时取消、临时文件清理、保护属性读回、浮窗点击穿透、隐藏状态保持、透明度和字体即时生效、WebSocket 重连、手机状态加载、Toast 发送/成功/失败区分、局域网未开启时端口不监听、端口变更不重复启动服务，以及 30 天历史清理。
